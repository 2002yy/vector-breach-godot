# 角色输入拥有者：视口边界续修

## 基线与原因

分支 `feat/character-runtime-inputs-20261023`，main 基线 `8f2dc7e8181a231df1f286bce8e68510a994ad7d`，增量从已验证头 `03ab625343246d3ad172936f0466c22af9be4ccf` 开始。PR #74 的旧头 Tests `39920566997`、Windows export/smoke `39920566998` 全成功；未解决的审查指出 `attach_character` 没有现场核对角色是否与拥有者属于同一视口。该审查项阻止合并，本批先补上接线前的隔离边界。

原 `configure` 只验证地图视觉根的视口；它并不能约束之后传给 `attach_character` 的角色。Vulkan 下用另一独立世界的 SubViewport 和真实 `t-blackwolf` 角色复现：旧代码接受该角色，触发 `foreign viewport must be rejected` 断言。原失败日志与截图保存在私有证据目录，没有修改原模型或贴图。

## 修复

`attach_character` 在构建合成对象、修改材质和登记角色前验证：拥有者仍在场景树且未等待删除；角色引用非空有效、仍在场景树、未等待删除且属于拥有者的同一视口。拒绝返回 null，不清空当前正确地图输入，不改现有角色绑定。合法同视口路径继续接受原参数。

`CharacterRuntimeBundleProbe` 新增独立 512×512 视口、真实角色、相机和照明，比较拒绝前后的全部逐表面活动材质/覆盖身份、登记数量及截图。另验证移出场景、null、同视口等待删除角色的拒绝。释放后的对象不能通过 Godot 的 Node 类型参数检查；初版测试误把它当作可调用参数，该测试脚本错误日志保留，最终用释放前的退出/删除边界验证，没有放宽 API 类型。
