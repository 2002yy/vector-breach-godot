## 循环比例：观察实际计数器并拒绝越界

新增过程/物理计数探针，记录每个采样的 engine process/physics frame、前置准备、物理内消费事件数；不只相信命令行或外部 supported 布尔值。每步检查前后处理帧差、是否已有预投递、是否发生内联回退。初始 tick 0 允许建立输入，之后要求实际一对一。

平地测试不依赖私有地图；处理频率由 `--fixed-fps` 控制虚拟循环步长，**不是 GPU 实测 FPS**。

| 处理 Hz / 物理 Hz | 实际相邻处理帧差 | 诊断支持 |
| --- | --- | --- |
| 60 / 60 | 1 | 支持 |
| 120 / 120 | 1 | 支持 |
| 30 / 60 | 0 或 1 | 不支持：部分物理步无前置准备 |
| 120 / 60 | 2 | 不支持：重复处理循环覆盖诊断 pending command |
| 60 / 120 | 0 或 1 | 不支持：部分物理步无前置准备 |

在 120/60 测试中，原生玩家实际收到了两次鼠标事件，但物理诊断的位移命令记录变成 0 次。这里丢的是队列诊断元数据，不能称正式游戏吞鼠标。当前队列没有处理这些比率的通用累积/消费问题，本片不扩成生产调度器。

严格驱动在真实 30/60 实图运行中，根据实际 `process_delta=0`、未预投递的 tick 2，写出 `accepted=false` 的拒绝凭据并以 **退出码 2** 结束；预期完整报告不存在。比例不符时不会悄悄回退后生成通过报告。这是拒绝不符合测量条件的作者输入，不是认定游戏在该比例下不能运行。
