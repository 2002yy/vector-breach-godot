# Movement-4 R3：各方案路线与实际 InputMap 键鼠事件

基线 `1e8d345cb821a9d94530aa676f0c198d2df46d18`（#98），分支 `audit/native-route-keyboard`。本片仅改作者工具、输入证据和 CI 定向检查；不改 PlayerController、移动规则/参数、正式 Current、原地图/资产、试玩菜单或包。Movement-4 尚未验收，Movement-5 继续冻结。

## 结果与边界

三方案分别通过原冻结 44 节点路线做反馈发现，录制实际 W/Shift 与鼠标像素事件，随后冻结并关闭反馈开环回放。原目标、半径、碰撞与导航身份保持。六条路线在 60/120 Hz 均无需跳跃、有原碰撞支撑到达，合计 **12/12 路线对照**：

| 方案 | 无跳前进 60 / 120 Hz | 静步 60 / 120 Hz |
| --- | --- | --- |
| Current | 4.417 / 4.408 s | 5.250 / 5.250 s |
| Legacy 1.6 | 5.967 / 6.000 s | 5.767 / 5.775 s |
| Modern CS | 5.033 / 5.033 s | 5.850 / 5.867 s |

这些是未优化的合成操控，不用于比较哪种方案“实战更快”。每方案自己的路线避免 R2 以 Current 时间线回放其他方案造成的误判。输入经 `Input.parse_input_event(InputEventKey/InputEventMouseMotion)`、现有 InputMap、实际玩家鼠标处理和实际移动采样入口进入物理；不再直接注入任意方向向量或修改玩家旋转。但仍是固定物理边界的无窗口合成事件，**不是 Windows 硬件输入、真实帧调度或真人手感验收**。

另外两种原跳跃输入分别转成真实键事件：三方案 × 两点 × 两频率共 **12 次跳跃，2 次首落点命中**（Current 预蹲两档）；其余保留圈外首落点，12 次均可落地后继续走入目标。这个采样只含 Mirage 两点，且原生按键边沿消费存在下一 tick 延迟，**不能与三图旧 20/24 或 52/90 横向比较，更不能回写旧成绩**。首落点、受支撑后续到达和输入合同三个目标分别存储。

## 排查出的测试环境问题

首轮六次路线均失败。仪器记录发现 headless 64px 后备窗口配合项目缩放，把注入的 `-120px` 转成玩家收到的 `-3000px`，导致转向环绕。原始失败和加仪器记录保存在本机；不将其视为玩家算法缺陷。

作者进程明确关闭内容缩放并设 1600×900 后，逐事件核对玩家收到的像素、鼠标处理前后 yaw 与灵敏度，证明未再次缩放；正式项目配置和鼠标实现不改。另用不依赖私有地图的平地探针检查 W/A/S/D、斜向归一化、Shift、Ctrl、空格、双向鼠标与释放状态，60/120 Hz 通过，并加入 CI。

空格事件注入的同 tick，`is_action_just_pressed()` 尚未消费，下一 tick 起跳；观测延迟 **1/60 与 1/120 秒**。保留请求、输入事件和消费时间，不人为提前输入或强制两档同数值；每条时间线检查按键边沿无丢失/重复且延迟不超过一 tick。原规则层与原生输入层的差异不能混为加速或起跳算法缺陷。
